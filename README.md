# FFmpeg Audio Processor with AWS Lambda & Terraform by Sew

This project sets up an **audio processing pipeline** using AWS Lambda and FFmpeg. Audio files uploaded to an S3 bucket (e.g., `.wav`, `.ogg`) are automatically converted to `.mp3` format using a Lambda function with a bundled FFmpeg binary.

---

## Project Structure

- `main.tf` — Terraform resources (Lambda, S3, IAM, etc.)
- `variables.tf` — Input variables for configuration
- `outputs.tf` — Useful output values after deployment
- `lambda_audio_processor/` — Lambda function code
- `script.sh` — Builds the FFmpeg Lambda layer (must be run before Terraform)
- `ffmpeg-python311.zip` — Zipped FFmpeg binary layer for Lambda (generated by script)
- `terraform.tfstate` — Terraform state file (ignored in version control)

---

## Setup Instructions

### 1. Prerequisites

- AWS CLI configured
- Docker installed
- Terraform installed

---

### 2. Generate the FFmpeg Lambda Layer

Before applying Terraform, you **must** build the FFmpeg static binary zip for Lambda:

```bash
./script.sh
```

## 3. NOTE !
Running `script.sh` - AWS do not like ffmpeg created on ARM CPU. It is better to run script on Intel machine.

## 4. Don't want to upload large file each time to test ?

Update below Lambda Event JSON to match the uploaded (source bucket) file name. My tested file 1h22min long and it has 850MB in size. Lambda compressed it to 44MB is size.

```
{
  "Records": [
    {
      "eventVersion": "2.1",
      "eventSource": "aws:s3",
      "awsRegion": "eu-west-2",
      "eventTime": "2025-08-03T11:32:00.000Z",
      "eventName": "s3:ObjectCreated:Put",
      "s3": {
        "bucket": {
          "name": "process-audio-files-source-production"
        },
        "object": {
          "key": "IWT_week_5.wav"
        }
      }
    }
  ]
}
```
